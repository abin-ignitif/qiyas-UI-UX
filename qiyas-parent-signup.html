Flow

Account details → verification → sign in

The verification code is the commit point. Until it is accepted, the account does not exist and the parent can safely edit the email or retry delivery.

Gap list

  • OTP delivery contractDefine delivery duration, resend cooldown, code expiry, and email-provider failure handling.
  • Account-creation transactionBackend must create the account atomically on accepted OTP and make the login redirect idempotent.
  • Password policy sourceConfirm the final minimum length and character rules before Flutter and React consume them.

Routing note

A completed OTP returns the parent to the existing login screen with the verified email available for prefill. Before OTP, the flow resumes at the last unfinished step and never opens a dashboard.

Decisions

Adult, bounded, and practical.

The screen does not try to motivate the parent. It earns trust by making the next step legible and by showing what happens when the parent leaves.

Reason before typingسطران فقط: أضف طفلك إلى قياس الليلة، وسنرسل رمز التحقق إلى بريدك.Two lines only: add your child tonight; the code goes to your email.
Email already registeredRecognition routes to parent login with the email carried over. It is not treated as a new-user rejection.
Consent and minor dataNot invented in the screen. Consent copy, privacy terms, and data-retention rules are product gaps listed below.
Do

Show 1 / 4, preserve typed values, and keep invitation inside the same continuous act.

Don’t

Add pricing, testimonials, trust seals, or a second solid action before the parent has an account.

Gap list

  • Minor-data consent and privacy contractThe screen needs the legal copy, consent storage, and retention policy before implementation.
  • Email delivery and resend contractDefine delivery states, cooldown duration, code expiry, and whether “check spam” is a help route or a system message.
  • Credential handoff formatDefine whether the child receives a password, a one-time link, or a code, plus expiry and share-sheet behavior.
  • Pricing or time estimateNo pricing was invented. If the parent must understand cost or time here, provide the approved product copy.

Architecture note

After account creation, the parent’s next route is stored as add-student. A relaunch resolves to that step until the handoff is complete. A blank parent dashboard is not a valid completion state for this flow.
