Screen 15 · Student exams

One question at first glance: can I take something right now?

The scheduled exams list puts availability before chronology. The filter bar is a five-column row under a three-month history note, every card ends in exactly one action, and the window a student can still enter is stated as an explicit time range. Arabic is primary; dates, durations, and counts stay LTR islands with tabular figures.

Resolution

Default to All and render each card from one status model so the badge, the action label, and the filter bucket can never disagree. Start is the only primary action; everything else is secondary, disabled with a reason, or a route to an existing runtime.

Rejected

A chronological transcript of the three-month window. Expired attempts compete with the exam open right now, and the student scrolls to find out whether anything is actionable.

Live preview

Both canvases render one state.

Theme, locale, filter, and the rules modal are driven by one render function; both surfaces show the same active content and never reset each other.

Gap list

Open decisions stay visible.

Not hidden in custom components. Each gap names what is missing and why the prototype stayed conservative.

  • Upcoming accent has no system colorThe reference build uses sky blue; the Qiyas palette reserves green for correctness and gold for achievement. Upcoming maps to state-info (green-tinted) pending a token decision.
  • Resume button treatmentThe reference build paints Resume amber-solid; solid fill belongs to the single primary action. Mapped to button-secondary + gold chip warn until the interaction owner confirms.
  • Live clock refreshStatuses derive from wall time. The refresh policy when a window opens or closes while the student is on the list (poll, push, on-focus) is a server decision.
  • Window paginationThe 3-month visibility window is assumed to fit one fetch. Pagination or virtualization beyond 50 items is unspecified.
  • Result deep link contractView Result routes to /student/exam/:id in production; this prototype links Screen 10 without an attempt parameter.
  • Arabic calendar and digitsar-SA defaults to Hijri; the prototype pins Gregorian with Western (latin) digits to match the numeral rule. Confirm product-wide.
  • Notification destinationThe bell is shell chrome in the spec’s header; its route and unread contract are not defined anywhere in the system yet.
  • Cooldown interplayIf the rules engine adds a retry cooldown to scheduled exams, the card needs a cooldown state; the badge ladder’s cooldown component is exam-attempt scoped today.
