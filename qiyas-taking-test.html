Screen 09 · Student runtime

One engine. Two unmistakable experiences.

Practice stays immediate and forgiving. Eligibility is deliberate, timed, and reviewable. Both modes reuse the same question and option components, while the threshold, clock, feedback timing, navigation, and exit language carry the stakes.

Resolution

The mode contract is persistent, not decorative: practice says feedback is immediate and has no timer; eligibility always shows remaining time, flag/review controls, and final-submit language.

Rejected

A color-coded shared header. It would make the distinction depend on memory and color, and it would spend green outside correctness.

Interactive handoff

Same state, two canvases.

The document controls synchronize mode, locale, theme, and runtime state. Arabic is primary. Mobile owns its 390px canvas and one 16px content inset, independent of the desktop host viewport.

Answering loop

Question types declare their rules before the options.

Latin A–D labels stay consistent in both locales; interface order mirrors, but labels and mathematics do not. This matches the existing authoring model and avoids maintaining two answer-label systems.

Single select
إذا كان x² + 5x + 6 = 0، فما جذرا المعادلة؟

One square marker. Selecting another option moves the selection.

Multi-select · all-or-nothing

Select every correct answer. A partial selection scores zero.
Long stem · one document scroll
تحرّكت نقطة على المستوى من A(-2,1) إلى B(4,5). إذا كان منتصف القطعة هو M، فأوجد إحداثيي M ثم حدّد ميل المستقيم AB.

Stem and options remain in normal flow. The screen scrolls once; options never sit in a second scrolling region.

Mode-specific states

Feedback teaches; the clock informs.

Practice explains every option after the student checks the answer and never auto-advances. Eligibility withholds feedback until results. Its timer changes weight and fill only—never pulse, sound, or motion.
