Native handoff

Native and Flutter begin at the same rest state.

The OS owns the first frame. The app owns the state machine. No zero-state animation is replayed after Flutter appears; the shared-element sequence begins from the native asset’s resting lockup.

Theme and locale resolution

Native follows the OS light/dark setting and device locale. Stored in-app preferences reconcile silently after Flutter’s first frame. If a stored preference differs, use the system’s 120ms reduced-motion crossfade between the two resolved rest surfaces; no flash and no layout jump.

Web first paint

Static HTML paints the page surface, lockup asset and safe-area-free optical centre before framework code. The first paint uses color-scheme and a server-resolved locale attribute; hydration only attaches routing and state listeners.

Exit landing rule

Student dashboard: lockup settles into the top start-aligned brand position. Parent dashboard: same top start-aligned position. Login and role picker: lockup settles into the unauthenticated shell’s optical centre. Reset and invite flows: lockup lands in the auth header. A destination without a logo uses a 120ms fade into its first surface.

Offline decision

Stored session plus no network proceeds with cached state; the splash does not add a blocking error. No session plus no network stays at rest, then shows the inline offline error and Retry after the timeout threshold.
