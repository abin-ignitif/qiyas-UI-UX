Screen 11 · Student badge exam

The event, stated before the clock.

The badge exam is a deliberate commitment: one sitting, a real cooldown if it is not cleared, and one earned badge at the end. The screen tells the truth before the student starts, then gets out of the way.

Resolution

Use a threshold screen, not a start button: duration, question range, coverage, running-clock behavior, cooldown, and retry rule all sit together before the commitment.

Rejected

A penalty-free withdrawal. It would let a student scout the exam and leave without consequence. Withdrawal is allowed, but it carries the same result as abandoning the attempt.

Interactive handoff

One event, twelve honest states.

The state control changes the same mobile and desktop exam canvases. Arabic is primary; questions, timers, review grids, and outcome paths preserve their intended LTR content where the system requires it.

Before committing

It is okay to wait for a real window.

The practical time check is raised once, plainly, because a three-hour exam started at 10:40pm is an avoidable bad experience. It is dismissible and does not block the student.

Quadratics and functions

  • Up to 120 questions across every cleared requirement
  • 180 minutes · the server clock continues if the app closes or the device goes offline
  • One Badge 3 award is on the line
  • Failing or withdrawing starts a 7-day cooldown
  • After the cooldown, the recommended retry path is targeted practice on named weaknesses
Time check · 10:40pm

You have up to 180 minutes. If you do not have that window, you can leave this screen and return later.

What the exam does not claim

Serious without pretending to proctor.

There is no integrity pledge, tab-switch warning, or monitoring language here. The exam is unproctored on a personal device; its value comes from taking it seriously.

Preflight decision

Battery and connection signals are not used to block the start. They are platform gaps, not reasons to create a false guarantee.

Long-haul structure

Orientation without turning the exam into a dashboard.

The review grid is always one deliberate tap away. The question remains the primary object; position and pace are visible but quiet. Sections and pause points remain unresolved until the exam model is confirmed.

Abandonment

Leaving is available, not ambiguous.

Chosen policy: allow withdrawal with the same consequence as an unfinished attempt. This gives a student their evening back without making the exam a reversible preview.

Modal · shown after Exit exam
Leave Badge 3 exam?

Your answers are saved. Leaving ends this attempt and the 7-day cooldown will begin. The same consequence applies if time expires.

Rejected alternatives

  • No withdrawalSimple, but teaches students to avoid starting a long exam when their circumstances change.
  • Penalty-free withdrawalKind in the moment, but makes scouting possible and weakens the event.

After failure

Two retry rules, one recommendation.

The current product rule is re-qualification. The alternative below uses the coverage report to target practice. Both are rendered so the product decision can be argued against the actual student experience.

Version A · current rule

Re-pass the eligibility tests.

After the 7-day cooldown, repeat the eight eligibility tests tied to Badge 3 before the exam unlocks.

Reads as repetition.

The student may have to re-prove concepts they already cleared, even when the coverage report names only two weak areas.

Version B · recommended

Practise the named weaknesses.

After the 7-day cooldown, the coverage report opens two or three targeted practice routes. The exam unlocks when that preparation condition is met.

Recommended.

It preserves consequence while making the cooldown a route back rather than a reset to a stack of old gates.

Gap list

Open decisions remain explicit.

These are product or platform contracts still needed before the badge exam can be production-ready.

  • Internal exam structureOpen: sections, difficulty ramp, and natural pause points versus one flat 120-question run.
  • Withdrawal policyRecommended here: withdrawal carries the same consequence as failure. Product approval is still required.
  • Practical preflight signalsOpen: whether battery or connection quality can be read, and whether showing them is useful without blocking the start.
  • Invalid question treatmentOpen: void, rescore, or free retry when a reported question is confirmed bad.
  • Partial attempt visibilityOpen: whether an abandoned exam appears in student history or only changes eligibility/cooldown state.
  • Retry ruleRecommendation: targeted practice after cooldown. Current alternative: re-pass every linked eligibility test.
  • Cooldown contractExample fixture uses 7 days and 2026-09-05. Production must receive the authoritative retry timestamp from the server.
  • Coverage report handoffOpen: define whether failure routes directly into Screen 12 or lets the student close the result first.
