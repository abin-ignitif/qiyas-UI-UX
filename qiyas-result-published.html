Screen · Published result · learner-web

The result is out. The record is complete.

The published, exam-by-exam result screen: the overall score leads, the exam record follows, and the performance summary uses the system’s own success and failure semantics. Arabic is primary; every figure stays an LTR island with tabular digits.

Resolution

Lead with the published result — percentage ring, score, and points earned — then the exam record and the summary metrics grouped by outcome. One exit back to scheduled exams.

Rejected

A countdown remnant or a flat list of raw counts. It would either suggest the result is still pending or bury the verdict under undifferentiated numbers.

Live preview

Published, final, exam by exam.

Theme and locale are driven by one render function. All values come from a single mock payload shaped like the API result contract; there is no pending state and no countdown.

State coverage

One published state, no pending residue.

The screen renders only when result_available is true. There is no countdown, no refresh prompt, and no hint that the result is still being prepared.

Gap list

Open decisions stay visible.

Not hidden in custom components. Each gap names what is missing and why the screen stayed conservative.

  • Result contract field namesThe payload (exam, date, started_at, duration_minutes, submitted_at, total_questions, score, summary) is an example contract; production must confirm the real endpoint fields.
  • Flagged and answered countsThe visible summary shows total, correct, wrong, and unanswered; whether flagged or answered counts are also returned is a product decision and the screen renders only what the payload provides.
  • Points definitionWhether points equal correct answers or a weighted score is a product decision; the screen renders the returned points value.
  • Review deep-linkPer-question review (qiyas-results-explanations.html) linking from this screen is unspecified.
  • Arabic calendar and digitsar-SA defaults to Hijri; the prototype pins Gregorian with Western digits to match the system numeral rule.

Flutter handoff

Keep both clients on the same result contract.

The web build consumes the CSS custom properties in this file; Flutter consumes the matching semantic values from the shared token source.

final qiyasResultPublishedTheme = ThemeData(
  scaffoldBackgroundColor: const Color(0xFFFEFEFE),
  colorScheme: const ColorScheme.light(
    primary: Color(0xFF11120F),          // Ink — Return to Scheduled Exams
    secondary: Color(0xFF0D662C),        // green — success badge, correct summary
    tertiary: Color(0xFFCE940F),         // gold — unanswered summary
    error: Color(0xFFC84B15),            // terracotta — wrong summary
    surface: Color(0xFFFEFEFE),
  ),
  textTheme: const TextTheme(
    headlineMedium: TextStyle(fontFamily: 'IBMPlexSansArabic', fontSize: 34, fontWeight: FontWeight.w700),
    titleMedium: TextStyle(fontFamily: 'IBMPlexSansArabic', fontSize: 17, fontWeight: FontWeight.w700),

    bodySmall: TextStyle(fontFamily: 'IBMPlexSansArabic', fontSize: 13, height: 1.55, color: Color(0xFF61665C)),
  ),
  // badge 72 · score clamp(44-56) · details/score two-column ≥680 · summary 3/2-col
);
