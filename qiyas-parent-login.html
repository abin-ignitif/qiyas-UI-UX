Decisions

Adult, cautious, unhurried.

The parent route answers legitimacy through restraint: a known shell, a clear form, a deliberate session choice, and no marketing copy.

3.1 Persistent session

Not persistent by default. Show an explicit “Keep me signed in on this device” checkbox, unchecked.

Rejected alternative

Always-on persistence is convenient but wrong for a shared tablet and a security-anchor account.

3.2 Biometric unlock

Do not offer it on the initial login. After a successful native login, a platform credential prompt may be offered once from account settings.

Rejected alternative

Prompting at the first login adds platform permission complexity before trust has been established.

3.3 Signup placement

Place “Create a parent account” below the primary submit, separated by the existing form-divider. It is findable, not competitive.

Rejected alternative

Putting signup beside the submit creates two equal calls to action for returning parents.

Security note

Login failure uses one message for incorrect email and password so the form is not an account-existence oracle. Logout will live under the parent shell’s Account destination, not on this form.

RTL proof

Mirror the layout, isolate the credentials.

Arabic labels, help, and errors follow the interface direction. Email and password remain LTR, with the reveal toggle on the logical end.

Motion

Quiet transitions only.

Parent login uses the existing quick and base tiers. The student login-to-dashboard signature sequence is not reused here.

Field and submit

Focus, reveal, inline errors, and pending submit use the canonical control transitions. Keep the form in flow when the keyboard opens and keep the focused field visible within the safe area.

Reduced motion

Remove travel and use the end state or a short cross-fade. No badge-ladder sweep, no shared-element signature, no decorative loading loop.

Engineer handoff

Parent login is a composition of named system parts.

Desktop uses the canonical unauthenticated shell with the existing badge ladder. Mobile collapses the brand panel and keeps the form within the keyboard-safe single-column rule.

Gap list

  • Biometric / platform credential promptNo cross-platform component exists in the system. Keep it out of the initial login; add a native-only credential enrollment pattern later.
  • Verification resend cooldownThe feedback ladder exists, but the exact resend timer behavior and email-delivery status are not specified. Product engineering should add the state contract before build.

Do / don’t

Do: keep the typed email, explain the next action, and preserve the parent’s control over session persistence.

Don’t: add badges, testimonials, trust seals, marketing copy, or a signature transition.
