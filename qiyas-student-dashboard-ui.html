Screen 06 · Student dashboard · learner-web

The dashboard answers one question first: what can I do right now?

Continue Practice and the exams open now lead; upcoming exams and subjects follow; progress and recent results sit in the quietest register. Desktop carries a persistent sidebar under the header, mobile a fixed footer navigation. Arabic is primary; numbers, times, scores, and counts stay LTR islands with tabular figures.

Resolution

One responsive screen with two navigation shapes: a collapsible sidebar from 820px starting under the full-width app bar, and a footer nav below 820px. Hierarchy is carried by border weight, heading size, and action prominence, not by labels.

Rejected

A uniform card grid with equal borders and an equal-weight filled action per section. It makes the student read everything before acting, and it flattens the difference between the exam that is open now and a result from last week.

Live preview

One screen, two navigation shapes.

Theme, locale, data state, and navigation are driven by one render function. The desktop canvas is a container at 820px and above with a collapsible sidebar under the header; the mobile canvas stays single column with the footer nav.

Gap list

Open decisions stay visible.

Not hidden in custom components. Each gap names what is missing and why the screen stayed conservative.

  • Nav rail and footer nav are new compositionsqiyas-design-system.html defines no navigation rail or bottom bar. Both are built from existing tokens (surface-raised, border-subtle, border-strong, radius-control) and need a system decision before Flutter ships.
  • learner-web is not defined in the projectThe brief names a target app; no repository, route table, or token package exists here, so the screen lives inside the Qiyas prototype.
  • Two dashboard surfaces now coexistqiyas-student-dashboard.html (Screen 06 handoff document) and this UI screen. Production routing must choose one deliberately.
  • Study time sourcestudy_time_minutes has no named aggregation rule; the prototype renders the raw value, including 0, and never estimates.
  • Progress definitionCompletion percentage appears per subject and overall. Whether it derives from badges, answered questions, or exam coverage is a product decision.
  • View all contractsUpcoming routes to qiyas-scheduled-exams.html and Results to qiyas-results-explanations.html; pagination and deep-link parameters are unspecified.
  • Exam runtime routingStart routes to /student/exam/:id in production; this prototype links qiyas-taking-test.html without an attempt parameter.
  • Arabic calendar and digitsar-SA defaults to Hijri; the prototype pins Gregorian with Western digits to match the system numeral rule. Confirm product-wide.
